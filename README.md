# wb-library-sync · 资料库本地同步

WorkBuddy 资料库 ↔ 本地，**两个方向都能跑**：

- **下载**（默认）：把空间里的文档、网页、数据表、网盘文件按账户分目录拉到本地
- **上传**（`--push`）：把本地文件/文件夹放回云端，自动按扩展名选路

> 名字里的 **sync** 是认真的：不是 pull，是双向。
> 上传侧的官方接口（`get-upload-credential` → 推 COS → `import-local-file`）
> 与下载侧共用同一套 `Range: bytes=0-0` 大小判据，两边的幂等逻辑是对称的。

**一个前提必须先说清楚**：官方**没有删除接口**，所以上传上去的节点删不掉。
因此上传侧的默认策略是**保守**——遇同名一律跳过，绝不制造第二份。

产出位置默认：

```
C:\Users\admin\Downloads\WbLib.cn\<账户uid>\<空间名>\...
```

实测：自己的 1 个空间、20 条资料 → **41 个文件 / 163 MB**，首次 25 秒；
第二次因跳过已有文件降到 **3.8 秒**。

---

## 一、为什么需要它

资料库里的东西只在云上，本机没有副本。想拿一个文件就得：
开网页 → 找到空间 → 逐个点开 → 右键下载。视频歌词工作流那 27 个节点（zip / mp4 / pptx / 多份 HTML），
手动点下来要十几分钟，而且拿不全。

这个工具一次跑完，目录结构按空间还原，**离线可用**。

## 二、怎么用

### 两个脚本，按范围分开

| 脚本 | 导什么 | 适合 |
|---|---|---|
| **`dlmine.bat`** | **只导你自己创建的空间** | 日常备份。默认推荐 |
| **`dlall.bat`** | 自己的 + 团队空间 | 要连同事/别人的共享空间一起归档 |

> **为什么分两个？** 团队空间通常是别人建的示例素材库，几百个文件里很多你用不上。
> 实测：你的个人资料只有 **20 条**，但加上一个团队空间后文件数飙到 **399 个 / 307MB**，
> 其中 357 个来自那个你只有 `reader` 权限的团队空间。所以默认只导自己的。

**日常用 `dlmine.bat`**，偶尔要全量才用 `dlall.bat`。

### 一句话版（推荐）

直接跟 WorkBuddy 说：

> **把资料库导到本地**

助手会自动申请授权并执行。要含团队空间就说：

> **把资料库全部空间导到本地**

> 原因：脚本需要 WorkBuddy 临时签发的一次性授权凭证，这一步由助手代劳最省事，
> 也不用你自己复制粘贴凭证。命令行直跑见下。

### 双击就能用（token.txt）

`token.txt` 放在项目目录里，两个 bat **会自动读取它**，所以你双击即可，无需传参。
让 WorkBuddy 刷新：

> **刷新我的资料库 token**

优先级：**命令行参数 `%~1` > `token.txt` > 提示**。

> **关于 token.txt**：它只是为了让「双击即用」成立，30 分钟后自动失效，
> 过期时 bat 会给出明确提示而不是晦涩报错。
> 它存的是你自己账号的短期凭证，**不放心就删掉**——删了就回到让我代劳的模式。

### 命令行版（`%1` 传 token，`%~2` 可传容量上限）

```bat
dlmine.bat op_xxxxxxxxxxxxxxxx
dlmine.bat op_xxxxxxxxxxxxxxxx 1024     :: 外加 1GB 总量上限
```

## 三、上传：把本地文件放回云端

下载是默认动作；加 `--push` 就变成上传。这也是项目叫 **sync** 而不是 pull 的原因。

### 怎么传

把文件或文件夹**拖到 `upmine.bat` 上**即可，或命令行：

```bat
upmine.bat "D:\backup\需求文档"
```

```bat
wblib.py --push "D:\backup\需求文档"                       :: 传到我的文档
wblib.py --push ./report.csv --space-id <id>              :: 传到指定空间
wblib.py --push ./folder --dry-run                         :: 只出计划，不传
```

流程与下载侧完全对称：**先看清单 → Y/N 确认 → 只传缺的**。

### 按扩展名自动选路

| 本地文件 | 变成什么 | 单文件上限 |
|---|---|---|
| `.md` / `.markdown` | 在线文档（可编辑） | 50 MB |
| `.html` / `.htm` / `.zip` | 页面 | 50 MB |
| `.csv` / `.tsv` | 数据表 | 50 MB |
| 其它 | 网盘文件 | 100 MB |

### 三件必须知道的事

**① 上传不可撤销。** 官方**没有删除接口**，所以传上去就删不掉。
这直接决定了本工具的两个默认行为：**不制造重复节点、遇到同名一律跳过**。

**② 目录结构会被打平。** 云端同样没有"建文件夹"的接口
（唯一的 `create-space` 建出来必定是团队空间）。
所以上传整个文件夹时，子目录不会重建，所有文件平铺到目标位置。

**③ 团队空间默认拒绝写入。** 目标是团队空间时直接中止，
必须看完清单后显式加 `--allow-team` 才提交。角色是 `reader` 的空间一律拒绝，
连确认环节都不进。

### 遇到同名怎么办：四态判定

| 状态 | 判定 | 默认行为 |
|---|---|---|
| `upload` | 云端没有同名 | 直接传 |
| `same` | 同名且大小一致 | 跳过（幂等） |
| `conflict` | 同名但大小不同 / 这类探不到大小 | **跳过**，不制造第二份 |
| `skip` | 空文件、超限、本地重名 | 跳过 |

大小判定用的还是下载侧那套 `Range: bytes=0-0` 判据。
但 **doc / page / database 没有可探大小的直链**，所以这三类只要撞名就按 `conflict` 处理。

`--overwrite` 的语义按类型区分，不假装一样：

- **网盘文件**：传 `nodeBlockId`，**原地替换内容**（节点 ID 不变、分享链接不变）
- **文档 / 页面 / 数据表**：接口不支持原地更新，只能**再建一份**
  —— 这点在清单里会明说，不让你稀里糊涂多出几个节点

## 四、删除：官方没接口，只能用打标代替

**先说结论：不管是你自己的还是团队的，文件/文件夹节点一个都删不掉。**
不是权限不够，是 WorkBuddy 资料库**压根没开放节点删除的 Agent 接口**
（官方 `mutation.md` 原文：「文件/文件夹节点删除没有正式 Agent API」）。
真正能删的只有三类：文档正文的块、数据表的字段、数据表的记录。

所以「一键删除」这条路是死的。退而求其次的办法是**改名打标**：

```bash
python wblib.py --mark-delete          # 给节点名加【待删】前缀
python wblib.py --mark-delete --yes    # 不问直接打
python wblib.py --mark-undo   --yes    # 撤销，名字恢复原样
```

打完标去网页搜索框搜 `【待删】`，要删的一次全出来，不用在几十上百条里翻。
改名可逆、不丢内容，所以可以放心先打标，再慢慢挑。

### 只想动其中几个？三个过滤器

| 参数 | 作用 | 例子 |
|---|---|---|
| `--mark-only 关键词` | **只处理**名称含这些词的 | `--mark-only 过来人,歌词` |
| `--mark-keep 关键词` | **跳过**名称含这些词的（保留不动） | `--mark-keep 歌词` |
| `--mark-pick 序号` | **只处理**清单里这些 `#N` | `--mark-pick 1,3,5-8` |

序号就是干跑打印里每行开头的 `#1` `#2`，支持 `5-8` 这种区间。
三个可以叠加，中英文逗号都认。动手前一律先 `--dry-run` 看一眼：

```bash
python wblib.py --mark-delete --dry-run --mark-keep 歌词   # 先预览谁会被跳过
python wblib.py --mark-undo   --dry-run --mark-pick 1-3    # 只还原前三个
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--mark-delete` | — | 加前缀打标 |
| `--mark-undo` | — | 去掉前缀撤销 |
| `--mark-prefix` | `【待删】` | 自定义前缀 |
| `--mark-only` / `--mark-keep` / `--mark-pick` | — | 上面那三个过滤器 |
| `--dry-run` | — | 只看清单不改名 |
| `--allow-team` | 关 | 打标默认只进个人空间，团队空间要显式确认 |

## 五、参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--out DIR` | `~/Downloads/WbLib.cn` | 输出根目录 |
| `--account NAME` | 自动取当前账号 uid | 账户目录名 |
| `--space-id ID` | 全部 | 只导指定空间 |
| `--kinds a,b,c` | 全部 | 只导指定类型：`drive,doc,web,database,link` |
| `--probe` | — | **先探测总量并给建议，不下载** |
| `--plan` | — | **出「远端/本地/待下载」对比表，再问 Y/N 是否下载** |
| `--plan-only` | — | 只出对比表，不询问不下载（bat 内部用） |
| `--yes`, `-y` | — | 配合 `--plan`：看完清单直接下载，不询问 |

| `--top N` | `15` | 清单显示条数 |
| `--max-total MB` | `0`（不限） | **总量门槛，超限就中止不下载** |
| `--max-size MB` | `0`（不限） | 单文件上限，超了就跳过 |
| `--overwrite` | — | 强制覆盖本地已有文件（默认跳过已有） |
| `--include-team` | — | 连团队空间一起导 |
| `--max-depth N` | `12` | 目录递归深度 |
| `--workers N` | `6` | 并发线程 |
| `--dry-run` | — | 只列清单不下载 |
| `--no-manifest` | — | 不写 `_manifest.json` |

**上传专用**

| 参数 | 默认 | 说明 |
|---|---|---|
| `--push PATH` | — | 上传哪个本地文件/目录。目录会递归展开 |
| `--space-id ID` | 我的文档 | 目标空间。省略时由服务端落到个人空间 |
| `--parent-id ID` | 空间根目录 | 目标目录节点，须与 `--space-id` 同属一个空间 |
| `--allow-team` | 关 | 确认后**才**允许写入团队空间 |
| `--overwrite` | 关 | 网盘文件原地替换；文档/页面/数据表会再建一份 |

### ① 本地已有会重复下载吗？**不会，默认跳过**

重复执行是**幂等**的。每个文件下载前用 Range 请求问一次远端大小，
和本地文件比对：**大小一致 ⇒ 跳过不重复下载**。

```bat
wblib.py          :: 第二次跑
已完成：新下载 3，本地已有跳过 24，用时 3.8s
```

实测第二次从 25 秒降到 **3.8 秒**，已有文件的修改时间原样保留（没被覆盖重写）。

只有两种情况会重下：
- 文件大小对不上（远端更新过 / 本地损坏）→ **明确报错**让你加 `--overwrite`，绝不静默覆盖
- 你显式加了 `--overwrite`

> `doc` 类无法预判远端大小（接口限制），所以每次都会重取正文。其余类型都能跳过。

### ② 先测一下有多大？`--probe`

```bat
wblib.py --probe
```

用 Range 请求（`bytes=0-0`）逐个问大小，**每个文件只花 1 字节流量**，秒级出结果：

```
  类型            条目      文件数            大小
  ----------------------------------------
  web           11       49      237.1 MB
  drive         13       13       72.1 MB
  doc            3        3           0 B  (大小不可预判)
  ----------------------------------------
  合计            27       65      309.2 MB

  ✓ 很小，放心导。
```

> **为什么能不下载就知道大小？** 资料库的 COS 预签名链接不支持 HEAD（403），
> 但支持带 Range 的 GET：发 `Range: bytes=0-0` 会返回
> `Content-Range: bytes 0-0/26819352`，看到总量而只下载 1 个字节。

### ③ 好几个 G 就不导了：`--max-total`

```bat
wblib.py --max-total 1024        :: 超过 1GB 就中止
```

先行估算，超限**一个文件都不下**，直接给出可操作的替代方案：

```
[门槛] 预估总量 309.2 MB
  ✗ 预估 309.2 MB 超过上限 100 MB，已中止，未下载任何文件。
    可选操作：
      · 调大上限    --max-total 471
      · 只导轻量    --kinds doc,database
      · 排除大视频  --kinds doc,database,web
      · 只看明细    --probe
```

### 双击 bat 的完整流程（`--plan`）

两个 bat 都是「**先看清楚，再问你要不要下**」，绝不闷头就下载：

```
================================================================
  导出计划
================================================================
  远端资料           27 条          309.2 MB
  本地已有           20 条          283.5 MB   已同步 OK
  --------------------------------------------------------
  ** 待下载 **        7 条           25.7 MB
                  其中 3 条为文档/数据表，大小不可预判（未计入上方数字）
================================================================

  待下载清单（按大小，前 7/7 条）：

            大小  类型       标题
  ------------------------------------------------------------
        9.3 MB  web      过来人_歌词跟唱版
        9.3 MB  web      过来人_歌词跟唱版
        7.0 MB  drive    过来人_歌词稿
       35.0 KB  drive    视频歌词工作流_工具包
            未知  doc      00_README
            未知  doc      云端网盘文件
            未知  doc      😁🤖和 Agent 一起用资料库

Download the missing items? [Y/n]:
```

回车或输入 `Y` 才下载；输入 `N` 直接退出，**一个字节都不下**。

### 清单按什么排序？`--sort`

双击时会让你选，也可命令行指定：

| 值 | 排序 | 适合什么时候 |
|---|---|---|
| **`size`**（默认） | 文件从大到小 | **最常用**。一眼看出谁在占空间，决定是否剔除大视频 |
| `time` | 最近更新在前 | 想看「最近动了哪些」，增量备份时确认变化 |
| `name` | 名称字典序 | 找某个具体文件时最快定位 |
| `type` | 先按类型分组，组内按大小 | 想按类别批量取舍（比如把 drive 全留、web 全跳过） |

> 个人建议**默认用 size**：导出的痛点几乎都是「被几个大文件撑爆」，
> 按大小排能直接判断要不要加 `--kinds doc,database` 把大件剔掉。
> 想回头确认近期改动时用 `time`。

```bat
wblib.py --plan --sort time      :: 按更新时间看
wblib.py --plan --sort name --top 50   :: 按名称，多显示一些
```

> **注意**：`--plan` 在管道/重定向环境下（stdin 不是真实终端）会自动判定为「不下载」，
> 这是**故意的安全兜底**——脚本化调用不会被意外卡在等待输入。
> 无人值守请用 `--plan --yes`；bat 走的是 `--plan-only` + 自己用 `set /p` 询问，
> 绕开了这个限制。

### ④ 有选择地导一部分

用 `--plan` 或直接双击 bat，在 Y/N 之前就能看清全貌再决定。

按**类型**筛（最常用）：

```bat
wblib.py --kinds doc,database         :: 只要文档和数据表，轻量
wblib.py --kinds doc,database,web     :: 排除视频/压缩包等大二进制
wblib.py --kinds drive                :: 只要原始文件
```

按**空间**筛：

```bat
wblib.py                              :: 只导自己的（默认，推荐）
wblib.py --include-team               :: 个人 + 团队
wblib.py --space-id <id>              :: 只导某一个空间
```

按**单文件大小**筛：

```bat
wblib.py --max-size 200               :: 单文件超过 200MB 就跳过
```

## 六、按节点类型怎么取的

不同类型的节点，走的接口完全不同：

| kind | 接口 | 落地格式 |
|---|---|---|
| `drive` / `smh` | `get-drive-file` 拿预签名 URL → 直拉 | 原文件（保持原扩展名） |
| `web` / `page` | `list-page-artifacts` 拿产物清单 → 逐个 GET | `<页面名>/` 目录，保留子结构 |
| `doc` | `get-doc-review` | `.md` |
| `database` | `get-database-content` | `.csv` |
| `link` | 不联网抓取 | 只在 manifest 里记原链接 |
| 目录节点 | — | 重建同名文件夹 |

`web` 页面是**完整单文件**：HTML 里内嵌了 base64 音频和图片，下下来 9~45 MB 一个文件，
双击就能播、能跳，不依赖任何 CDN。

## 七、目录结构

第一层是**账户 uid**——同一个 WorkBuddy 可以登多个账号，分开存不会互相覆盖：

```
Downloads\WbLib.cn\
└── 80f100bf-3143-45b0-be87-1d17ddfa774b\        ← 账户 uid
    ├── space_j3pVzsU2DSLDUJGHZ6h7T7\            ← 空间（未命名时用 id）
    │   ├── 00_README.md
    │   ├── 过来人_歌词跟唱版\过来人_歌词跟唱版.html
    │   ├── 云端网盘文件\腾讯2025中期报告.pdf      ← 子目录被还原
    │   └── ...
    ├── 🚀资料库的100种用法\                       ← 团队空间
    │   └── 孙北北面包店同款-...\
    │       └── 孙北北面包经营管理工作台\

```

`_manifest.json` 记录每个节点的成功/失败/原因，换机器或重建备份时用它核对。

## 八、踩过的坑 & 解决

### 1. 中文文件名导致页面静默丢失（最隐蔽）

产物 URL 里的中文文件名没做百分号编码，`urllib` 直接抛
`UnicodeEncodeError: 'ascii' codec can't encode characters`。

**危险之处**：异常被 `except Exception` 吞掉后页面仍报「成功」，
但磁盘上一个文件都没有——**假成功**。

修法：`urllib.parse.quote` 逐段编码 path，并加断言校验「实际落盘数 > 0」，
杜绝静默失败。

### 2. 目录树根层不能传 `parentNodeId=spaceId`

会报 `code=11510 block not found`。根层只能传 `spaceId`，
子层才传 `parentNodeId`。

### 3. `docs/` 这类路径会被本机安全策略拦截

资料库的页面产物里常见 `docs/`、`desktop/`、`download/` 等目录段，
写盘时可能被拦。已加路径改写（`docs/` → `_docs/`）+ 失败后退回平铺文件名。

### 4. `get-database-content` 只认 `databaseId`

而 `list-node` / `node-info` **都不返回** `databaseId`——这是个接口缺口。
处理方式：先试把 nodeId 当 databaseId，失败则从同空间 page 的 HTML 里
扫 `databaseId: "xxx"` 字面量（沿用官方 `clone-flow.md` 的同一判据）。

### 5. 部分 doc 服务端就取不到

4 篇文档报 `code=50000 doc convert failed`。
**这是服务端限制，不是本工具的 bug**——用官方 `doc/get_doc_reviews.py` 直接调同样失败。
已在失败明细里如实标注，重试有时能过（`retry` 做了 3 次指数退避）。

### 7. 服务端不返回文件大小

`get-drive-file` 只给 `{nodeId, fileName, ext, downloadUrl}`，**没有 size 字段**；
`list-page-artifacts` 的产物同理。

要「先知道多大再决定下不下」，只有一条路：**带 Range 的 GET**。
`HEAD` 会被 COS 预签名拒绝（403），但 `Range: bytes=0-0` 返回 206 + `Content-Range`，
既能拿到精确总量又只花 1 字节——总量预估、跳过已有文件、断点续传三件事全靠它。

### 9. 双击 bat 时会撞见两个隐性杀手

都是「表面报错、真因被吞」，排查花了不少功夫，记下来免得再踩：

**① PowerShell 重定向 stdin 会塞进 UTF-8 BOM**

```python
token repr = '\ufeffop_9ba9...'   # 30 字符，本该 29
UnicodeEncodeError: 'latin-1' codec can't encode character '\ufeff'
```

业务侧只能看到被 `_common` 吞成的 `code=TEMPORARY_ERROR`，极难定位。
修法：在任何读取发生前把 BOM 吃掉（`strip_stdin_bom()`）。

**② 同名节点会撞同一路径**

资料库里同名节点很常见（重复上传过）。用户个人空间实测就有 5 组：
`过来人产物包` ×3、`歌词跟唱版` / `歌词完整版` / `手机版` / `480P视频` 各 ×2。

不处理的后果：**后面的覆盖前面的（静默丢内容）**，且差异对账误报成
「内容不一致」。修法：同名组内按 node id 排序，第一个保留原名，
其余加 `__<id前8位>` 后缀（`disambiguate()`），保证结果稳定可复现。

**③ 页面目录里会混入子节点的产物**

子数据表节点会落在父页面目录下，若把整个目录都计入本地大小，
会误报 10 条「内容不一致」。修法：对账只统计该节点**自己的产物清单**
（`probe_item_size()` 第三项返回 own paths）。

> 这三个坑的共同点：**都是「看着像网络/服务端问题，实则是本地细节」**。
> 排查方法一致——在 API 调用外层套 traceback，把被 `_common` 吞掉的
> `__cause__` 打印出来，真因立刻现形。

`_common.py` 已做输出脱敏（`token/cookie/authorization` 正则打码）。
本工具额外确保：token 只从 stdin 读、只存在内存变量、不写文件不进环境变量、
不回显到任何输出里。

## 九、安全边界

**下载链路是只读的**，上传链路会写入：

- 下载只调 `list-*` / `get-*` / `*-artifacts`，**不碰任何创建、修改、删除、移动接口**。
  默认是下载，必须显式 `--push` 才会走写入。
- **上传链路的三道闸**：
  1. 团队空间默认拒绝，要 `--allow-team` 才提交；
  2. `reader` / `invalid` 角色直接拒绝，连确认环节都不进；
  3. 撞名一律跳过 —— 因为**官方没有删除接口**，多出来的节点删不掉。
- **不做的事**：没有删除、移动、重命名、建文件夹。这些要么接口不存在，
  要么会扩大影响范围，本工具一律不碰。
- token 绝不落盘、不跨进程复用；`token.txt` 仅作双击便利之用，~30 分钟过期。
  **不放心就随手删掉它**，下次让我刷新即可。
- `.gitignore` 已把 `token.txt` / `*.token` 挡在仓库外 —— 这是为了能安全地把
  项目传到 GitHub 而加的。**凭证泄露比工具本身重要得多。**
- **下载幂等**：本地已有且大小一致的文件不重复下载，也不覆盖重写
  （`--overwrite` 才强制重下）；大小不一致时报错而非静默覆盖。
- 输出目录下的写入默认都是新建，**不会覆盖源文件**。
- Windows 保留名（`CON`/`NUL`/`COM1`…）、非法字符、超长路径都已处理。

## 十一、数字说明（避免误会）

最后一次全量实测：

| 范围 | 顶层条目 | 磁盘文件 | 体积 |
|---|---|---|---|
| 你自己的空间 | **20** | 41 | 163 MB |
| ＋ 1 个团队空间 | 89 | **399** | 307 MB |

**「399 个文件」不等于「399 条资料」**。
一个 `web` 页面节点在本地会展开成它自己的一整套资源（HTML + 图片 + JS + CSS），
那两个各 50MB 的宣传页单独就占了 217 个文件。

你自己的资料实际是 **20 条**：13 个文件 + 7 个页面。用 `dlmine.bat` 就是这么多。

依赖：**无第三方包**。只用 Python 标准库，
鉴权与 HTTP 层直接复用 WorkBuddy 内置 library skill 的 `_common.py`。

> Python 3.9+ 即可（官方 library skill 最低要求 3.9）。
> 首次使用若提示找不到 `_common.py`，说明内置「资料库」skill 未安装，
> 用 `--library-path` 显式指定它的目录。
